# AI (Phase 4) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A user can talk to the assistant about their project, accept or reject its proposed edits inline, repair a broken document with **Fix with AI**, ask for a **Review paper**, and keep resumable threads whose titles are generated by the model and can be regenerated.

**Architecture:** The browser posts a turn to `POST /api/projects/:projectId/chat` and reads an SSE stream. The route resolves the caller's BYOK key (or the owner-only server key), builds a bounded context from Postgres, calls the OpenAI-compatible Kilo Code gateway with streaming tool calls, executes read-only tools and the compile tool server-side, and turns `write_file`/`edit_file`/`create_file`/`delete_file` into diff proposals. The browser renders each proposal in a Monaco diff widget; Accept applies the hunks to the editor buffer and saves through the existing document PATCH (the database stays the source of truth), Reject discards it. Threads and messages persist in `chat_threads` / `chat_messages`; the first assistant reply triggers a fire-and-forget fast-model title.

**Tech Stack:** Node 26.13.0, TypeScript 6.0.3, Next 16.4.5 (App Router, route handlers, SSE), React 19.3.1, Drizzle ORM + Postgres 16, Redis + BullMQ (existing compile queue), `diff` (jsdiff) for hunks, Vitest 5.1.0, Playwright 1.65.0.

**Spec:** `zenno/specs/2026-11-07-spektrum-design.md` (authoritative for *what*; §6.4 composer, §7.4 inline affordances, §12 AI, §16 Phase 4 row, §18 D11–D12, §19.4 AI contracts). Phase 3 handoffs: `zenno/plans/2026-11-07-03-compile-pdf-logs.md` (compile route, render store, Logs panel, editor client).

## Global Constraints

- **Pinned toolchain** (spec §3.2): Node **26.13.0**, pnpm **12.18.0**, TypeScript **6.0.3**, Next **16.4.5**, React **19.3.1**, Tailwind **4.3.5**, Drizzle **0.45.4**, zod **4.6.7**, Vitest **5.1.0**, Playwright **1.65.0**. **TypeScript 6 stays for this phase** (D72); the TS 7 switch is a separate spike after Phase 4.
- **The key never reaches the client.** `/api/user/llm-key` returns only `{configured, last4}`. Every gateway call goes through `/api/llm/*` or the chat route; the `Authorization` header is never logged, echoed in SSE, or included in an error message.
- **Ownership on every route**: every project/thread/document handler resolves `requireUser()` and inner-joins `projects` on `id AND ownerId AND deletedAt IS NULL`. Unknown or malformed ids → 404, never 500 (Phase 2/3 precedent).
- **Mutating routes** call `assertSameOrigin(req, loadWebEnv().authUrl)`; read-only routes do not. The chat POST is rate-limited with `BUDGETS.ai` (30 / 60 s / user) → 429 + `Retry-After`.
- **SSE events** (spec §12.6, amended by D73): `meta`, `thinking`, `text`, `tool_call`, `tool_result`, `diff`, `title`, `done`, `error`. JSON payloads are validated by the zod schemas in `packages/shared/src/ai.ts`.
- **Tool list** (spec §12.4 + §19.4, amended by D73): `list_files`, `read_file`, `write_file`, `edit_file`, `create_file`, `delete_file`, `compile`, `get_logs`, `search_project`. Defined once in `packages/shared/src/ai/tools.ts`; the proxy and the client import the same types.
- **Edits are proposals, never server mutations.** `write_file` / `edit_file` / `create_file` / `delete_file` return a `DiffProposal`; the model is told the user must accept. The client applies hunks to the editor buffer and saves with the existing `PATCH /api/projects/:projectId/documents/:documentId` (409 on stale `baseUpdatedAt`). No new write path for document content.
- **System prompt, Fix prompt, Review prompt and Title prompt are verbatim** from spec §12.5/§12.7 (Appendix B). No invented copy beyond Appendix B.
- **Icons**: every `<svg>` has `viewBox="0 0 16 16"` and uses `currentColor` only; no emoji (spec §5.8/§15.2). Reuse `IconSparkle`, `IconStop`, `IconArrowUp`; add an icon only if missing.
- **Visual budget**: `pnpm test:visual` stays `continue-on-error: true`; ratios are recorded, not a gate (spec §15.1). The hard exit criteria are behavioural (below).
- **e2e runs serially** (`workers: 1`); the AI e2e uses a local mock gateway, never a real key.
- **DB-backed unit tests clean up** in `afterAll` (the web Vitest project shares one database; follow `apps/web/src/app/api/projects/documents.test.ts:66-71`). One manual real-gateway check happens after merge.
- **`exactOptionalPropertyTypes: true`** (`tsconfig.base.json`): build optional fields with conditional spreads (`...(x ? {x} : {})`); never write `{x: undefined}`.
- **Every new dependency runs `pnpm install` and commits `pnpm-lock.yaml`** (CI uses `--frozen-lockfile`). The only new runtime dependency is `diff` (it ships its own types; `@types/diff` is not added); no AI SDK is added — the gateway is called with `fetch`.

## Review Focus

The spec implies these failure modes but no happy path exercises them. Each line names the test that pins it, in the task that owns the code.

1. **A diff goes stale.** The user edits the buffer after a proposal arrives; Accept must not apply a patch that no longer matches. → `applyHunks` throws and the widget shows `The document changed since this suggestion — re-run?` (Task 5/11).
2. **A tool tries to read or edit outside the project.** `../other-project/main.tex`, absolute paths, and another owner's document must be rejected, not served. → tool unit tests (Task 6) and the cross-owner chat 404 (Task 13).
3. **The API key leaks.** It must not appear in the SSE stream, the `llm_usage` row, the error body, or the browser bundle. → key-resolution unit test (Task 3) and the e2e missing-key case (Task 13).
4. **The model emits a malformed or unknown tool call.** The stream must end with an `error` event and a persisted partial assistant message, never hang or silently drop the turn. → gateway/tool-loop tests (Task 2/8).
5. **Title generation fails or races.** A gateway error, an unparsable JSON reply, or a control character keeps the 60-character fallback; the chat never waits for the title. → title unit tests (Task 7) and the e2e title case (Task 13).
6. **The context exceeds 120 000 tokens.** The drop order is history (7) → bib keys (4) → touched files (3); the main document, the selection and the manifest are never dropped; if the main document alone is over budget it is truncated with a marker. → context unit tests (Task 4).
7. **A user without a key opens an AI surface.** The composer is disabled with `Add your API key in Settings`; the route returns 403 even if the client is bypassed. → composer test (Task 9) and e2e (Task 13).
8. **A compile tool call outlives the stream.** The compile tool waits for the render row and the route sends a heartbeat while it waits; a 35 s timeout returns a tool error, not a hang. → compile-tool unit test (Task 6).
9. **The current turn is dropped or duplicated.** History is read **before** the new message is appended; the final user message is always last and never dropped. → route test (Task 8).
10. **Accept of a create/delete proposal.** A created file has no baseline and a deleted file has no content, so the replace path cannot be reused; each kind has its own write path and tests. → widget tests (Task 11), e2e create/delete (Task 13).
11. **Accept of a proposal for a non-active file.** The active-document autosave closure would write the proposal's content into the wrong document row; Accept must open the target path and save against that path's id. → non-active-path widget test (Task 11), e2e create/delete (Task 13).

## What Phase 4 ships (and what it deliberately does not)

Ships: the chat proxy (SSE, streaming, tool loop, thinking levels, BYOK/server-key resolution, usage rows, rate limit), the context builder with the 120 k budget, the nine tools, diff proposals + Monaco diff widget + accept/reject/accept-all + stale detection, the composer transcript and empty state, the `Review paper` pill, `Fix with AI` (per diagnostic and all), thread persistence, model-generated titles + regenerate/rename/delete, the Settings API-key card, the AI e2e with a mock gateway, and three visual baselines.

Does not ship: streaming auto-apply (no `inlineAutoApply` field exists in the preferences schema; adding it is a later spec change), voice mode, file upload in the composer, a model picker, real-time collaboration, Prism conversation import (Phase 5), and a production gateway account (the owner supplies `LLM_API_KEY`; Phase 5 documents rotation).

## Appendix D — Decision log additions

- **D72 — TypeScript 6.0.3 stays for Phase 4.** The TS 7 native compiler is a separate spike; switching now would put the AI phase's deadline at risk for no user-visible gain.
- **D73 — The chat route is `POST /api/projects/:projectId/chat`** (supersedes §12.6's `/api/llm/chat`), emits the §12.6 events plus `title`, and exposes `get_logs` + `search_project` (reconciles §12.4 with §19.4). The route needs `projectId` for context, ownership and persistence; a generic `/api/llm/chat` cannot enforce any of them.
- **D74 — Edits are client-applied proposals.** The server never writes document content from a tool call; Accept applies hunks to the editor buffer and saves through the existing PATCH (409 on stale). This preserves the single write path and the revision hash.
- **D75 — The gateway is called with `fetch`, not an SDK.** The OpenAI-compatible SSE shape is small, pinned by tests, and avoids a new dependency tree; the only new runtime dependency is `diff`.
- **D76 — Context is a labelled block, not native chat turns.** The spec lists history as context item 7; a single labelled `<history>` block keeps the drop order and the token budget testable. Prompt injection containment is the Accept gate (D74) and the verbatim system prompt, not the labels.
- **D77 — Title generation is fire-and-forget after `done`.** The title call uses `maxOutput:64` (a superset of §12.7's ~20) so the mock can match `max_tokens <= 64`; recorded as a deliberate deviation. The route sends `done` as soon as the assistant reply is persisted, then runs `generateTitle` with a 2 s cap and enqueues `title` if the stream is still open. The client keeps reading until EOF (it does not treat `done` as stream completion). A failure leaves the fallback and sends nothing.
- **D78 — The AI e2e uses a local mock gateway on port 4010** started by `playwright.config.ts`; CI never needs a real key. One manual real-gateway check is recorded after merge.
- **D79 — The e2e owner uses the server key (`LLM_API_KEY`) because the server key is owner-only (spec §12.2); the member-without-key case proves the disabled surface and the 403.**
- **D80 — Visual baselines for the composer/thread/diff are measurements, not gates** (`continue-on-error: true`, spec §15.1); the phase's exit criteria are behavioural.
- **D81 — `diff` is `9.0.0`.** It ships its own types and `structuredPatch`/`StructuredPatchHunk`; `@types/diff` is a deprecated stub and is not added.
- **D82 — Accept is per kind.** `replace` applies hunks to the editor and saves; `create` creates the document then patches it; `delete` resolves the id and deletes. The server never writes document content from a tool call.
- **D83 — The chat route reads history before appending the new message.** The final user message is the last model message and is never dropped by the context budget.
- **D84 — The AI e2e is a separate Playwright config** (`playwright.ai.config.ts`, `pnpm test:ai`) with its own `reuseExistingServer: false` servers and an S3-free seed; the default e2e config ignores `ai.spec.ts` so a developer's `pnpm dev` cannot silently point at the real gateway. The seed also inserts a failed `pdf_renders` row for the owner project so `Fix with AI` has a diagnostic without a worker/texlive/S3.
- **D85 — `/api/inference/models` is rate-limited and cached.** It consumes `BUDGETS.ai` per user and caches the gateway result for 60 s; it is not an unmetered outbound call.
- **D86 — Composer slot amendment.** The empty state keeps the 88 px slot; a thread with parts uses a 64 px composer rect (§6.4) inside a `min(45vh, 420px)` scrollable transcript area. This is a layout amendment, not a replacement of §6.4.
