# Editor Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the inert dashboard rows with the real Spektrum editor — a Monaco surface with Prism's two themes, LaTeX/BibTeX/CSV grammars and folding, a resizable project sidebar with file CRUD, persistent tabs, debounced autosave, the settings modal and its six sections, and the composer shell — so that opening a project, editing, switching tabs and hard-refreshing all survive a reload.

**Architecture:** `apps/web` stays a Next.js 16 App Router app. The editor route is a server component at `/u/[projectId]` that authenticates, resolves the project and document tree, and renders one client island (`editor-client.tsx`) which owns tabs, the Monaco instance, autosave and the dialogs. Documents are read and written through route handlers under `/api/projects/:projectId`; the database is the source of truth and the browser buffer is a cache (§11.0). Preferences are one JSONB row per user, served by `/api/user/preferences`; only `interfaceTheme` is mirrored to `localStorage` (under the existing `crixet_light_mode_preference_v1` key) so the pre-paint script can pick the right theme before hydration. Monaco is bundled locally (no CDN), themed from `zenno/recon/extracted/monaco-themes.js`, and loaded only on the client.

**Tech Stack:** Node **26.13.0**, pnpm **12.18.0**, TypeScript **6.0.3** (`strict`), Next.js **16.4.5**, React **19.3.1**, Tailwind CSS **4.3.5**, Drizzle ORM **0.45.4**, Radix UI primitives, `monaco-editor` **0.57.0**, `monaco-vim` **0.4.4**, Playwright **1.65.0** + `pixelmatch` **8** + `pngjs` **7**.

**Spec:** `zenno/specs/2026-11-07-spektrum-design.md` (read §6.3, §7, §9.6, §9.7, §11.0, §15, §19.2, §19.5 first). The spec is the authority on *what*; this plan is the authority on *how*. Where a measurement in this plan disagrees with the spec, the measurement wins and Task 1 amends the spec.

**Read the Next.js docs first.** `apps/web/AGENTS.md` warns that this Next 16 has breaking changes and training knowledge is wrong. Before writing any Next.js code (Task 4 onward), read the doc index in the repo-root `AGENTS.md` and the relevant guides under `apps/web/node_modules/next/dist/docs/` — especially `01-app/02-guides/lazy-loading.md` (`ssr: false` only inside client components), `01-app/03-api-reference/03-file-conventions/dynamic-routes.md`, `01-app/03-api-reference/04-functions/cookies.md`, and `01-app/03-api-reference/03-file-conventions/route.md`.

**Exit criteria:** `pnpm typecheck`, `pnpm lint`, `pnpm test`, `pnpm build` green; the new behavioural e2e suite green; a manual pass opens a project, edits, switches tabs and hard-refreshes with the text intact. The visual suite runs 2 editor and 6 settings baselines and **records** the ratios; it is **not** a release gate, exactly like the accepted Phase 1 shortfall (see `zenno/plans/2026-11-07-01-shell-dashboard.md` Appendix A).

## Global Constraints

- Node **26.13.0**, pnpm **12.18.0**, TypeScript **6.0.3** strict. Never bump a pin inside a task.
- Next.js **16.4.5**: Turbopack default, `proxy.ts` never `middleware.ts`, async-only `cookies()/headers()/params/searchParams`. `params` and `searchParams` are `Promise`s in pages and route handlers.
- **All UI copy is verbatim from the spec** or from the Phase 2 copy sheet (Appendix C). No invented labels; every addition is a numbered decision.
- **No emoji, no icon fonts, no Unicode glyphs as icons.** Every icon is an inline SVG in `packages/ui/src/icons/`, `viewBox="0 0 16 16"`, `currentColor` only (§5.8).
- **Every colour comes from `tokens.css`.** No hard-coded hex in components; the Monaco theme data is the single exception (it is a transcription of Prism's theme object and lives in `apps/web/src/editor/themes.ts`).
- **Every mutating route** calls `requireUser()`, `assertSameOrigin()`, validates with zod at the boundary, and returns `errorResponse(e)` on failure.
- **No `dangerouslySetInnerHTML`.** No PDF rendering, no AI, no compile worker, no object storage, no spellcheck service, no equation hover, no folder UI in Phase 2 (Appendix D).
- Every task ends in a commit. No task leaves the tree red in `typecheck`, `lint`, `test` or `build`.
- The database is the source of truth (§11.0). A save response's `updatedAt` is the next `baseUpdatedAt`; never trust the client clock.

## Review Focus

These are the failure modes the spec implies but no single screen capture exercises. Each has a test in the task that owns the code.

1. **Two tabs on the same document.** The later save must lose cleanly: the loser reloads the winner's content and keeps its cursor, and neither tab can silently overwrite the other.
2. **Leaving before the 400 ms debounce fires.** Tab switch, route change, window blur and hard reload must flush the buffer; typing then refreshing immediately must not lose the last keystrokes.
3. **Stale tab state.** `localStorage` may reference a file that was renamed or deleted; reloading must drop phantom tabs, never crash, and still open the URL's `?p=` file.
4. **Monaco lifecycle.** Switching files repeatedly must preserve per-file cursor/scroll and must not leak models, editors, listeners or workers; unmounting the route disposes everything.
5. **Hostile paths.** Create/rename must reject `../`, absolute paths, backslashes, empty names, over-long names and collisions with an existing path, without ever corrupting the tree or losing the document id.

## What Phase 2 ships (and what it deliberately does not)

**Ships**

- Route `/u/[projectId]?p=<path>`; dashboard project name links to it.
- Project sidebar: project header, `Files`/`Chats` tabs, search, `+`, file list, bottom user chip, account menu.
- File CRUD: create, rename, delete, download (text files), filtered by `hiddenFiles`.
- Monaco: local bundle, `crixet`/`crixet-light` themes, verbatim options, per-file models and view state.
- LaTeX, BibTeX and CSV Monarch grammars; three folding providers; LaTeX language configuration.
- Tabs: open/close/activate/rename, URL sync, `localStorage` persistence, per-file cursor restore.
- Autosave: 400 ms debounce, flush on switch/blur/`Cmd/Ctrl+S`, `409` conflict reload, `Save failed` chip.
- Composer shell: textarea autogrow to five lines, `Thinking:` selector, `+` menu, mic, disabled send.
- Settings modal: 960×720, six sections, all §9.6 controls, preferences persisted server-side.
- Keyboard shortcuts dialog.
- Custom editor context menu (§7.5) and a file-search overlay.
- A static pre-compile right pane (`Initializing...`), which is exactly the state in both Phase 2 editor captures; Phase 3 replaces its internals.

**Deliberately does not ship** (Appendix D): PDF rendering, compile, logs, SyncTeX, AI/chat threads, image/binary documents and uploads, spellcheck service, equation hover, folder creation/grouping, import/export, embedding/`\input` awareness, collaboration.

**Explicitly accepted risk:** the visual budget remains ≤ 0.15 % per baseline, but it is a measurement target, not a CI gate. The Phase 1 acceptance is not re-litigated. Task 20 runs a single geometry pass and records the final ratios; it must not become another calibration spiral.

```ts
export async function PATCH(req: NextRequest, ctx: { params: Promise<{ projectId: string; documentId: string }> }) {
  try {
    const user = await requireUser();
    assertSameOrigin(req, loadWebEnv().authUrl);
    const { projectId, documentId } = await ctx.params;
    const body = saveSchema.parse(await req.json());
    return NextResponse.json(await saveDocument(user.id, projectId, documentId, body.content, body.baseUpdatedAt));
  } catch (e) {
    if (e instanceof StaleDocumentError) {
      return NextResponse.json({ error: "conflict", document: e.current }, { status: 409 });
    }
    if (e instanceof DocumentPathError) {
      return NextResponse.json({ error: "bad_request", message: e.code }, { status: 400 });
    }
    if (e instanceof DuplicatePathError) {
      return NextResponse.json({ error: "duplicate_path" }, { status: 409 });
    }
    return errorResponse(e);
  }
}
```

`zod` schemas: `{ content: z.string().max(524_288), baseUpdatedAt: z.string().datetime() }`, `{ path: z.string().min(1).max(200) }`. Unknown project/document → 404 `{ error: "not_found" }` (not 403). The download route uses `Content-Disposition: attachment; filename="<basename>"` with the basename JSON-quoted and any `"`/CR/LF stripped.

- [ ] **Step 4: Implement the hook**

State in refs: `baseline`, `savedValue`, `inFlight`, `timer`, `pending`. `schedule()` marks dirty, clears and restarts a 400 ms timer; on fire, if `getValue() === savedValue` do nothing; else send. If a request is in flight, set `pending = true` and return; when it resolves, if `pending`, send once more. `flush()` cancels the timer and awaits the current + pending chain. ## Appendix B — Fixtures

- **`editor` dataset** — exactly one project named `New Project` with `main.tex` = `BLANK_MAIN_TEX`, `main_document_id` set, no other projects, no folders, and the owner's `user_preferences` row deleted.
