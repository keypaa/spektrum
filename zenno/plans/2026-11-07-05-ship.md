# Phase 5 — Ship Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Spektrum as a host-agnostic production kit — a Prism import/export with a byte-exact round trip, a reference Docker deployment (web + worker + Caddy + Postgres + Redis + MinIO), backups, health/metrics/logging, security hardening, admin access, a load test, and a launch runbook — with no dependency on a specific cloud provider.

**Architecture:** The Next.js app stays the only user-facing surface; the existing BullMQ worker stays the only compile process. Import/export are server-side: a security-validated streaming zip reader feeds a pure parser that turns a Prism archive into project drafts, and a DB writer persists them idempotently. The deployment kit is a single `docker compose` project that runs unchanged on any Docker host; every host-specific value is an env var. Security is a first-class input class: zip-slip, zip bombs, oversize bodies, cross-origin, ownership, secret leakage and metrics exposure all get explicit rejection paths and tests.

**Tech Stack:** Next.js 16.4.5 (App Router, Node runtime), React 19, TypeScript 6.0.3, Drizzle 0.45.4 + Postgres 16, Redis 7 + BullMQ, S3-compatible storage (MinIO), Better Auth 1.7.18, vitest 5, Playwright, `fflate` (zip), `prom-client` (metrics), `@sentry/nextjs` (optional error tracking), Caddy 2, Docker Compose.

**Spec:** `zenno/specs/2026-11-07-spektrum-design.md` — §13 (files, import, export), §10.5/§10.6 (auth/rate limits/hardening), §19 (API), §17 (open items). This plan adds the deployment and operations detail the spec defers to Phase 5.

## Global Constraints

- Node **26.13.0**, pnpm **12.18.0**; TypeScript **6.0.3**, `strict`, `exactOptionalPropertyTypes`, `noUncheckedIndexedAccess`; no `any` in exported signatures.
- Every mutating route: `requireUser()` → `assertSameOrigin(req, loadWebEnv().authUrl)` → `zod` parse → ownership → `errorResponse(e)`.
- `errorResponse` status contract: `UnauthorizedError` 401, `ForbiddenError` 403 (429 when suspended), `CsrfError` 403, `ZodError` 400, `SyntaxError` 400, else 500 generic.
- All copy verbatim from the spec; no emoji; icons 16×16 `currentColor`; colors from `tokens.css`.
- Host-agnostic: no cloud SDK/CLI/URL in app code; host values come from env.
- The real Prism export fixture is `e2e/fixtures/prism-projects-2026-11-05.zip` (copy of `/home/keypaa/Downloads/prism-projects-2026-11-05.zip`, 3 385 111 bytes, 15 projects). It is the round-trip oracle.
- Import limits live in the env schema (Task 12): `IMPORT_MAX_FILE_BYTES=26_214_400`, `IMPORT_MAX_TOTAL_BYTES=536_870_912`, `IMPORT_MAX_ENTRIES=50_000`, `IMPORT_MAX_RATIO=100`, `IMPORT_MAX_PROJECTS=200`. The web and worker read them through `loadWebEnv()`/`loadWorkerEnv()` and pass them into `readZip`/`parsePrismArchive`.
- The document inline-content cap is **524 288** UTF-16 code units; larger text and all binaries go to the `uploads` bucket with `blobKey` and `content = null`.
- Uploads are capped at 30 MB by Caddy and `experimental.proxyClientMaxBodySize` (Next's proxy buffers 10 MB by default — Task 4 raises it).

## Review Focus

Security-critical inputs, each with the task that tests it:

1. **Zip-slip / traversal / absolute / backslash / control / over-long paths** → reject the entry, never write outside the project (Task 2). Validated on the **full** entry path before grouping.
2. **Symlink / directory entries** — the importer never writes files to disk (it stores bytes as `documents`), so a symlink entry is inert bytes; directory entries and macOS junk (`__MACOSX/`, `.DS_Store`) are dropped (Task 2). No mode-based claim is made (fflate exposes no mode).
3. **Zip bomb / oversize / entry-count** → the streaming reader counts **actual** inflated bytes and aborts past the per-file/total caps, and checks the declared size/ratio/count from the central directory (Task 1). A forged declared size is caught by the actual-byte counter; a compressible entry over the per-file cap is rejected (Task 1).
4. **Oversize multipart body / file** → 413, never a 500; `content-length` is checked before `formData()`, and `proxyClientMaxBodySize` is raised (Task 4).
5. **Cross-origin import/export** → 403 (`assertSameOrigin`); **another owner's export** → 404, never 200 (Task 6).
6. **Secret leakage** — `SENTRY_DSN`, S3 keys, LLM keys and the BYOK key never appear in metrics labels, logs or error bodies (Tasks 15–17).
7. **Metrics/health exposure** — `/api/metrics` requires `METRICS_TOKEN` (fail closed in production) and is allow-listed in `proxy.ts`; `/api/health` is unauthenticated but exposes no internals (Task 15).
8. **docker.sock exposure** — only the worker mounts it; the compose file and launch doc say why and what limits the blast radius (Tasks 10, 20).
9. **Supply chain** — `fflate`, `prom-client`, `@sentry/nextjs` are pure-JS, pinned; `pnpm audit --prod` is a CI gate (Task 17).

- [ ] **Step 3: Implement `readZip` / `writeZip`**

`readZip` uses `new Unzip((file) => { … })` and `unzip.push(bytes, true)`:
- In the callback: increment an entry count; when it exceeds `maxEntries`, set `failure = new ZipError("too_many")` and `unzip.terminate()`. Reject when `file.originalSize > maxFileBytes` (`too_large`) or `file.originalSize / Math.max(1, file.size) > maxRatio` (`ratio`) **before** consuming data (set `failure` + `terminate()`).
- Accumulate chunks in `file.ondata`; add `chunk.length` to a running `total` and a per-entry `size`; if either exceeds its cap, set `failure = new ZipError("too_large")` and `unzip.terminate()` (the backstop for a forged declared size).
- On `final`, push `{ path: file.name, data: concat(chunks), originalSize: file.originalSize, compressedSize: file.size }`.
- After `unzip.push`, `if (failure) throw failure` — fflate may swallow a throw raised inside the callback, so capture it and rethrow.
`writeZip` uses `zipSync(files, { level: 6 })`.

- [ ] **Step 3: Implement `parsePrismArchive`**

1. **Validate each entry's full path first** (before grouping): reject when empty, absolute (`/` prefix), over 200 chars, contains `\`, control chars, or any `.`/`..` segment; push the original path to `rejectedPaths` and skip. Use the same rules as `normalizeDocumentPath`.
2. Drop directory entries (path ends with `/`), `__MACOSX/`, `.DS_Store`, and a root-level `spektrum-export.json`.
3. Group the rest by the first path segment; ignore entries with no directory segment (stray root files).
4. Drop `preview/`. Keep `conversations/` aside.
5. Re-root `uploads/` and `prism-uploads/`: move contents to the project root; on collision keep the directory prefix. For every `.tex`, rewrite `\includegraphics[...]{uploads/<name>}` and `\includegraphics[...]{prism-uploads/<name>}` (and the leading-`/` form) to the same with `<name>`; record `{from,to}`.
6. `main.tex` → `mainPath`; else promote the largest `.tex` containing `\documentclass` (`promotedMain = true`); else `null`.
7. Conversations: `items[]` → for each item, `message` → role from `content[].type` (`input_text` → user, `output_text` → assistant; join `text`), `function_call*` / `apply_patch*` → `tool` turn with the item's name/arguments; `status:"unsupported"` → `{skipped:true, reason}`. Title = first user text truncated to 60 chars.
8. `kind` by extension; `text` = UTF-8 decode for text kinds (tex/bib/csv/other with no NUL byte), else `null`.
9. Cap projects at `limits.maxProjects ?? 200` and per-file bytes at `limits.maxFileBytes ?? 26_214_400`.
10. `ParsedArchive.rejectedPaths` is the aggregate of every project's `rejectedPaths`; the importer reports both (the top-level list is the one shown in the UI).
